実ブラウザで検証し、2 件の問題をすべて修正してコミットしました。

問題 1: 伸長(日跨ぎ)したイベントが month で DnD 不可 → 解決

原因: shouldBlockMonthDnd が view==='month' && !isFullDayEvent で 判定していた。isFullDayEvent は isSameDay を要求するため、フルデイイベントを month で伸長して日跨ぎ（マルチデイ）化すると isFullDayEvent が false になり、以後 month で操作不可になる。

修正 (slot.ts / commit 6e5e085): ブロック対象を 「単日の時間イベント」だけに絞る。

view === 'month' && isSameDay(start, end) && !isFullDayEvent(start, end)

- 単日時間イベント（9:00–10:00）→ ブロック（対策2 の意図どおり）
- フルデイ / 日跨ぎ → 操作可（伸長後も引き続き伸縮できる）

実ブラウザ確認: フルデイ・日跨ぎイベントは EW リサイズアンカー 2  つ保持、単日時間イベントは 0 つ（アンカー非表示 = 伸縮不可）。

問題 2: フルデイイベントの色が変わらない → 解決

原因（根因特定）: globalStyle(':global(.rbc-event-allday)', ...)  と :global() ラッパを付けたのが誤り。vanilla-extract の globalStyle は selector 引数が既にグローバル前提であり、:global() を付けるとビルド後 CSS にリテラルの :global(...) がそのまま残り、ブラウザが 無効セレクタとしてルール全体を破棄していた。加えて特異度も rbc 既 定色に負けていた（同値・後方勝ち）。

修正 (CalendarView.css.ts / commit 03b68a9):
- :global() ラッパを除去
- 特異度を .rbc-event.rbc-event-allday（(0,2,0)）に上げ、rbc 既定 .rbc-event{background:#3174ad}（(0,1,0)）より順序非依存で勝たせる

実ブラウザ確認: フルデイイベント（日跨ぎサンプル / TEST-fullday-2359 / パソコンの前が楽 / 1日オフ）が #00695c（Teal 800）で表示。単 日時間イベントは #3174ad のまま区別可能。
