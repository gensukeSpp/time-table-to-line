修正完了です。原因と対応をまとめます。

原因

src/components/pages/TimelinePage.tsx の itemRenderer 内、選択中（selected === true）の分岐で

ts
node.style.removeProperty('background-color');


と「background-color を削除」していました。これは「ライブラリの選 択色 #ffc107 を素通しさせる」意図でしたが、実ブラウザでは選択背景 ごと消えて透明になるのが実挙動です（マイルストーン未所属イベントは !decor.backgroundColor のガードでこの分岐に入らないため正常に見えていました）。

ライブラリ（vendored 0.30.0-beta.4）は選択色を ed = { background: "#ffc107" } として getItemStyle() で合成し、React の style prop 経由で background に書きます。ref は単なるオブジェクト保持（xi()）で imperative に色を書くわけではない、という事実も今回確認しました（参照ドキュメントの記述が実挙動と食い違っていました）。

修正

removeProperty をやめ、選択中も #ffc107 を !important で明示適用するようにしました。

ts
node.style.setProperty('background-color', selected ? '#ffc107' : decor.backgroundColor, 'important');
if (!selected && decor.opacity != null) node.style.opacity = String(decor.opacity);


- 未選択時 → マイルストーン色
- 選択中 → ライブラリ選択色と同じ rgb(255, 193, 7)
- 待機不透明度 0.7 は未選択時のみ適用（従来どおり）

!important だからレンダー毎に React の通常優先度の書き込みに勝ち、選択/解除で色が消えたり戻る問題（色戻り）は従来どおり解消されます 。
