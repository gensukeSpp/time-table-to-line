**丸め** に関係なく、両方同じ動作(`.rbc-row` に追加)ができたのはなぜですか? 
---

- id 30 TEST-dateless (0:00–0:00, 丸めなし) → rbc-event（.rbc-row 内・クラス無し）
- id 32 1日オフ (0:00–23:59, 丸めあり) → rbc-event rbc-event-allday（.rbc-row 内・クラス有り）

つまり 2 つは同じ場所（.rbc-row）にあるが、クラスの有無が違います。これがなぜか、というのが質問への答えです。

なぜ両方 .rbc-row に入るのか — 別々の経路だから

react-big-calendar (TimeGrid.js:293) は、イベントを上部バンドへ振り分けるとき次の条件を OR で満たすものを .rbc-row へ送ります:


accessors.allDay(event)            …① allDay 扱い
|| startAndEndAreDateOnly(start,end)  …② 日時が「両方 0:00」(date-only)
|| (日跨ぎ)                          …③ 複数日にまたがる


- id 30（0:00–0:00）は ② date-only に該当 → バンドへ。※ allDayAccessor は false（isFullDayEvent が false だから）
- id 32（0:00–23:59）は ① allDay（allDayAccessor = isFullDayEvent が true）に該当 → バンドへ

end_time の丸め（0:00 か 23:59 か）はこの配置条件には効きません。両者を 週のどこに置くか は「②で入るか ①で入るか」の違いであって、到達先の .rbc-row は同じだからです。

丸めの本当の役割 — .rbc-event-allday クラスの付与（有無）

クラスは EventCell.js:60,81 で決まり、配置とは別信号です:


showAsAllDay = isAllDay || allDayAccessor(event) || (日跨ぎ diff>1)
→ true のとき rbc-event-allday を付与


- id 30（0:00–0:00）: allDay=false、日跨ぎでもない -> rbc-event-allday 付かない
- id 32（0:00–23:59 丸め）: allDayAccessor（=isFullDayEvent）が true -> rbc-event-allday 付く

つまり 丸め（23:59 にする）の目的は、イベントに allDayAccessor を真にさせ、.rbc-event-allday クラスを持たせることです。.rbc-row 配置ではありません。

補足（比較の注意点）

- id 30 は「0:00–0:00」という date-only の特殊ケースで、②の経路から偶然バンドに入っています。日跨ぎ扱いではない 2 者でも、丸めなしを「0:00–1:00」のような普通の時間イベントで作ると、時間列 .rbc-time-content に落ちます（丸めが無いとバンドにも入らずクラスも付かない）。
- この「同じ .rbc-row に居るだけでは month 作成イベントを区別できない」という点こそ、issue #29 が クラス付与（＝丸め）を必須にし、次の issue #30 が .rbc-event-allday を識別子に使う理由です。id 32（丸めあり）はクラスで区別可能で、id 30（丸めなし）は区別できません。

まとめると、丸めは「.rbc-row に置くか」ではなく「rbc-event-allday クラスを付けるか」に効いており、両者が同じ場所に見えるのは、片方が date-only の別経路で入ったためです。


では、普段使いでは、 date-only なしですね。
---

その通りです。

修正後は、普段の月ビュークリック作成は必ず end_time = endOfDay(slotStartTime) = 23:59:59.999（resolveEventEnd で丸め）になります。なので日々の操作で date-only（0:00–0:00）のイベントが新規生成されることはありません。id 30 の TEST-dateless は、私が事前調査用に API  から直接入れた特別なテストデータで、通常運用では発生しない経路です。

補足として、2 点だけ念のため:

1. 過去データ: DB に既に date-only（0:00–0:00）で保存されているイベントは今後も存在し、週表示では .rbc-row に出ます（ただし rbc-event-allday は付かない）。これは既存データであり、今回の修正は新規作成経路のみを直すので、変換は行いません。
2. 他経路: date-only は「たまたま両端が 0:00 のイベント」が作られたときだけ発生します。通常の月クリックでは起こらず、もし将来そのよ うなイベントが生まれれば allDayAccessor は false のまま（クラス無し・date-only 経路でバンド入り）になります。

つまり普段は allDay 経路（0:00–23:59、rbc-event-allday 付き）だけになり、month 作成イベントはクラスで確実に区別できる、という理解で 正しいです。
