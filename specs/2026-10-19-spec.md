# Issue #41 — 'closed' のマイルストーンのイベントを参照

## 1. 目的 / ユーザーストーリー

「閉じたマイルストーン」について、**何を完了して closed としたか**を後から確認できるようにする。closed マイルストーンを達成日の新しい順に一覧し、そのマイルストーンに属する「完了」イベントのタイトル → `staff_id` / グループ名 / 終了日時 を **3 段構成**で辿る。**管理者のみ**が操作・閲覧できる。

1. タイムラインの「マイルストーン作成」ボタンの**下**にある「閉じたマイルストーン」ボタンをクリック（admin のみ表示）
2. 右スライド（Mantine `Drawer position="right"`）に、closed マイルストーンの「タイトル」「達成日」が**達成日基準の降順**で並ぶ
3. マイルストーン行をクリック → そのマイルストーン所属イベントのうち **`progress` が「完了」のものだけ**がアコーディオンリストで開く
4. イベント行の**開閉ボタン（chevron）**またはタイトルをクリック → `staff_id` / グループ名 / **`end_time`** を表示

## 2. 決定仕様

### 2-1. API 契約（バックエンド新規）

`GET /milestone/closed`（**新規**）

| 項目 | 仕様 |
|------|------|
| 認可 | `require_token` + `claims["admin"]` が偽なら **403** `{"detail": "admin only"}` |
| 対象 | `MilestoneORM.status == "closed"` のみ（open / waiting は含まない） |
| 並び順 | `.order_by(accomplished_date.is_(None), accomplished_date.desc())` — **達成日降順、達成日 NULL は末尾** |
| 返り値 | `[MilestoneORM.to_dict()]`（`id / staff_id / title / description / color / status / created_at / guideline_end_date / accomplished_date`） |

```python
@router.get("/milestone/closed")
def get_closed_milestones(claims=Depends(require_token), db=Depends(get_db)):
    if not claims.get("admin"):
        raise HTTPException(status_code=403, detail="admin only")
    rows = (
        db.query(MilestoneORM)
        .filter(MilestoneORM.status == MILESTONE_CLOSED)
        .order_by(MilestoneORM.accomplished_date.is_(None), MilestoneORM.accomplished_date.desc())
        .all()
    )
    return [m.to_dict() for m in rows]
```

**なぜ新設したか（D1）:** `GET /milestone/all` は `status in (open, waiting)` 固定で **closed を返さない**ため、closed 一覧を取得する手段が存在しなかった。`/milestone/all?status=closed` へ拡張する案は既存契約（open + waiting）を壊すため不採用。

### 2-2. 既存 `GET /milestone/closed/{milestone_id}/events`（据え置き）

- **admin 限定のまま変更しない**（非 admin 403、closed 以外・存在しない ID は 404）。
- 返り値は各イベント dict（`group_name` 込み、`summary` は返さない）。**`progress` の絞り込みはフロントで行う**（Issue 実装要件「取得後 `"progress": "完了"` で絞る」）。

### 2-3. 決定事項

| ID | 決定 |
|----|------|
| D1 | closed 一覧用に `GET /milestone/closed`（admin 限定）を新設 |
| D2 | 並び順は `accomplished_date IS NULL` → `accomplished_date DESC`。`DELETE /milestone/remove` 由来の closed は達成日が **NULL** のため末尾に固定し、表示は「達成日なし」 |
| D3 | 完了イベントの絞り込みは**フロント**で `normalizeProgressGroup(progress) === '完了'`。英字トークン `complete` も「完了」に正規化（既存ヘルパを再利用） |
| D4 | 3 段構成は Mantine `Drawer` + **自前の開閉 state**（`Accordion` ではなく `UnstyledButton`）。タイトルクリックで「開閉」と「1 行三点リーダー → 2 行」を同時に行うため。**開閉アニメーションは `Collapse`（既定 200ms ease）** で付与し Issue #40 の Accordion と同等にする。段 3 のイベント行には**開閉ボタン（chevron）**を併設 |
| D5 | タイトル clamp スタイル（1 行 ⇄ 2 行）は `src/components/molecules/clampText.css.ts` に抽出し Issue #40 の Drawer と共有（コピペ禁止） |
| D6 | ボタンは `admin` のみ表示。バックエンドも 403 で二重防御。closed events の権限は据え置き |
| D7 | closed 一覧・closed イベントは「開いたときにだけ」取得（`enabled` ゲート）。`invalidateMilestoneList` は closed 一覧も無効化する |

### フィードバック反映履歴（2026-10-19）
1. **開閉アニメーション**（Issue 本文では打ち消し線）— ユーザー要望により Mantine `Collapse`（200ms ease）で追加。`Collapse` は閉時も子を保持するため畳むアニメーションも成立し、子クエリは `enabled` 連動で閉時は取得しない。
2. **イベントタイトルの開閉ボタン** — 3 段構成を明示するため `ActionIcon` + 自前 SVG chevron を追加（開時 90 度回転、タイトルクリックとも併用）。アイコンライブラリは追加せずインライン SVG。

## 6. 補足・注意点

- **`Collapse` は閉時も子を DOM に保持**する（`height:0` + `inert` + `aria-hidden`）。そのためコンポーネントテストの可視判定は `aria-expanded` / `aria-hidden` ベースで行う（`toBeInTheDocument` だけでは可視性を検証できない）。
- `ClosedMilestoneDrawer.test.tsx` のイベント取得 mock は `mockImplementation((id) => id === 1 ? events : [])` とし、行ごとの内容を分けている（`Collapse` により全行の子がマウントされるため、同一データを返すと要素が重複する）。
- 「終了日時」のアサートは UTC ISO `end` をローカル TZ 表示するため、分のみ（`\d{2}:30`）を検証する（Issue #40 と同じ方針）。
- 打ち消し線の残り部分（**矢印アイコン無しの枠**）は未実装。必要なら `ClosedMilestoneRow` に枠スタイルを追加するだけで対応できる。
- バックエンドのテスト実行は `.venv/bin/python -m pytest`（`.python-version` の py3.13 が pyenv 未インストールのため素の `python` は失敗）。
