加えて、レビューの「waiting -> closed 実状態遷移」の件については、現状の設計では UI に削除ボタンを出さない方針を維持しています。
理由:
- サーバー契約は `DELETE /milestone/remove/{id}` → `{"closed": milestone_id}` で、これは単なる見た目ではなく状態遷移そのものです
- 同時に `TimelineEventProps.completed = true` の自動完了と紐づける影響範囲が大きく、別 Issue で整理した方が安全です
- そのため、この PR は「管理者権限の担保」と「更新画面の制限」に絞り、削除/closed 実体化は後続対応に分離するのが妥当です
