# Issue #40 — 'open', 'waiting' 状態マイルストーンのイベント参照

## 1. 目的 / ユーザーストーリー

各マイルストーンタイトル右の '...' ボタンから、所属イベントを progress 別アコーディオンで閲覧できるようにする。マイルストーンはグループ横断共有（requirement-03）のため、所属イベントも**一般ユーザー（非 admin）が閲覧可**（編集は従来の権限に従う）。

1. マイルストーンタイトル右の '...' をクリック
2. 右からスライドで、指定マイルストーン以下に progress（「これから」「まだ」「もうすぐ」「完了」「指定なし」）の開閉付きアコーディオン一覧を表示
3. 開くと各イベントの「タイトル」一覧 → さらに「スタッフID」「グループ名」「開始日時」を表示

## 2. 決定仕様

### 2-1. API 契約（バックエンド改修）

`GET /milestone/{milestone_id}/events`（open + waiting 対象）

- **権限: admin gate 撤去 → `require_token` のみ**（一般ユーザー閲覧可）。closed 用 `GET /milestone/closed/{milestone_id}/events` は admin 限定のまま変更しない。
- レスポンス: `[EventORM.to_dict()]` に **`group_name` を追加**した配列（下記 D1）。
- `group_name` はイベントの `group`（group_id）から `Team.SHORTNAME` を引く。Team 未登録なら `null`。

レスポンス要素:
```jsonc
{
  "id": 12, "staff_id": 1001, "group": 3, "group_name": "グループA",
  "start": "2026-08-02T10:00:00.000Z", "end": "2026-08-02T11:00:00.000Z",
  "title": "child", "summary": null, "progress": "これから",
  "milestone_id": 9, "completed": false
}
```

### 2-2. 決定 D1 — `group_id → group_name` はフロント解決不可 → バックエンド委譲

- `GET /group-names` は `[SHORTNAME]` のみ（CODE 無し）で ID→名前マップを作れない。
- `GET /group/users` はメンバーのかなのみでグループ名を持たない。
- `/timetable/inquiry` は自分のグループ名のみ（他グループのイベントには使えない）。
- **結論:** フロントで解決不可のため、`/milestone/{id}/events` のレスポンスに `group_name` を付与する（Issue の「不可能ならバックエンドに一旦委譲」に該当）。

### 2-3. 決定 D2 — 閲覧権限の緩和

- '...' ボタンは全ユーザーに表示（`MilestoneList` は admin でゲートしない）ため、非 admin でもスライドが開けるよう open/waiting 用エンドポイントの admin gate を撤去。イベント**編集**は従来どおり既存権限。

## 6. 補足・注意点

- Drawer テストの「開始日時」assertion は実行環境 JST のため時刻を `\d{2}:\d{2}` に緩和（UTC `start` を date-fns でローカル表示する仕様）。意図（開始日時が表示される）は不変。
- バックエンド旧仕様書 `light_token_server/specs/2026-10-13-milestone-event-retrieval-spec.md` の「管理者のみ閲覧可」記述は本 Issue で**撤回**（D2）。open/waiting 用は `require_token`、closed 用は admin のまま。
