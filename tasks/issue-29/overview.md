# Issue #29 — overview.md

## 目的
これまで 'week' ビューで生じていた「時間ごとのイベント追加」に加えて、'month' ビューからは「その日 1 日いっぱい（フルデイ）のイベント」として区別して追加できるようにする。

- 操作手順は 'week' と同じく「スロットクリック → タイトル追加ダイアログ → イベント追加 → イベントクリック → 詳細ダイアログ」
- 'month' で追加したイベントは `start_time: 0:00 / end_time: 23:59`（フルデイ）で保存し、'week' ビューでは `.rbc-row`（上部バンド）に置いて区別する

## ユーザーストーリー
- タイムテーブルの **'month' ビュー**で、ある日のセルをクリックしてタイトルを入力し「追加」→ **その日 1 日分のイベント**が作成される
- **'week' ビュー**に切り替えると、そのイベントは上部の `.rbc-row`（all-day バンド）に表示され、時間列のイベントと明確に区別できる
- 'month' ビューで作成したことが分かるよう、イベントに `.rbc-event-allday` クラスが付与されている（次 Issue #30 の前提）

## スコープ
### 実装するもの
- 'month' クリック時の作成経路で `end_time` を同日 `endOfDay`（23:59:59.999）にする
- 'month' 由来イベント（フルデイ）を react-big-calendar の `allDay` として扱い、週ビューの `.rbc-row` 配置 + `.rbc-event-allday` クラス付与を達成
- `currentView === 'month'` を前提として日時を作分岐させ、'week' の動作を変えない
### 対象外
- ドラッグ&ドロップによる伸縮の正確な挙動（スコープ外）※ issue 原文を尊重
- バックエンド / DB スキーマ変更（不要）
- 真の日跨ぎイベント作成 UI（YAGNI）

## 前提・依存
- フロントエンド: `react-big-calendar` 1.20.0（本件の挙動の根拠）、`date-fns` 4.4.0（date-fns 統一方針）
- 既存修正 `tasks/task-08/`（11PM 問題）: `src/lib/slot.ts` の `resolveSlotEnd`（23:00 → 同日 endOfDay に丸め）。本件はこれを**拡張**する（既存 'week' 23:00 作成は壊さない）
- バックエンド API `POST /event/add` は任意の `start_time` / `end_time`（ISO 文字列）を受け付ける → **バックエンド変更は不要**
- rbc の `allDayAccessor` は現在 `() => false`（task-08 の防御）。本件でフルデイ時のみ真を返す**条件付き**に変える

## リスク・トレードオフ・未解決点
1. **`allDayAccessor` を条件付きにする影響**（最重要）
   - react-big-calendar は `allDay` なイベントを週ビューでは `.rbc-row` に、月ビューでは月セル内（`rbc-event-allday` クラス付き）に描画する。フルデイ（0:00–23:59）イベントのみが `allDay` になるよう判定するので、既存の 'week' 作成イベント・既存の日付のみイベント（0:00–0:00）・日跨ぎイベントの振る舞いは**変わらない**。
   - ただし `allDay=true` なイベントの DnD 伸縮/移動は週バンド内で異なる挙動になり得る → issue スコープ外として許容。実ブラウザで確認し、許容できない場合の代替（カスタム className を併用し `allDayAccessor` は戻す）を test-plan に記載。
2. **既存の「月クリックで作った 0:00–1:00 イベント」**：本修正は新規作成経路のみ直す。過去に作られた 0:00–1:00 イベントは `isFullDayEvent` に合致しない（end 1:00）ため週ビューの時間列に残る。データ移行は対象外（イベント 31 等を確認用に残す）。
3. **フルデイ判定の曖昧さ**：`start=0:00 かつ end=23:59` をフルデイとみなすため、万一「丁度 0:00–23:59」の手作りイベントがあれば `allDay` 扱いになる。実用上は望ましい挙動。
4. **Storybook (`src/stories/Calendar.stories.tsx`)**：`onSlotInfo` シグネチャに `view` が増えるが、`action('onSlotInfo')` は任意引数を受け取るため互換。コンパイル確認だけ行う。
